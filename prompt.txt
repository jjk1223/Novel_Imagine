# 角色与任务
你现在是一位资深的 AI 全栈工程师，精通 React/Next.js, Python FastAPI, LLM Agent 架构（如 LangGraph/原生编排）以及 Neo4j 图数据库。
你的任务是协助我从零开始，搭建一个“自动化小说创作系统”。

# 项目概述
这是一个前后端分离的 Web 应用。用户输入初步的小说大纲和构想，系统将自动扩写大纲、规划章节、逐章撰写正文，并实时提取人物关系生成可视化图谱。整个思考和生成过程必须通过流式传输（Streaming）在前端实时可见。

# 技术栈约束
- **前端:** Next.js (React), Tailwind CSS, React Flow (或 ECharts) 用于关系图谱渲染。
- **后端:** Python FastAPI (用于提供 RESTful API 和 SSE 流式接口)。
- **AI/Agent 层:** 大模型支持配置qwen模型或者本地的ollama模型，使用原生 Python 异步生成器或 LangGraph 编排多 Agent 工作流。
- **数据库:** - 关系型: SQLite (方便本地开发，存储小说章节信息)。
  - 图数据库: Neo4j (存储人物实体及其关系，我本地已经有该镜像)。

# 核心功能模块与 Agent 设计
系统需要包含以下三个核心 Agent 能力：
1. **Planner Agent:** 接收用户输入（世界观、题材、几句话构思），输出扩写后的完整大纲和结构化的《章节目录》。
2. **Writer Agent:** 基于 Planner 的输出，并结合已生成的上下文（Memory），逐章进行流式撰写。
3. **Graph Extractor Agent:** 异步分析新生成的章节文本，提取新出现的人物及人物关系的变动，输出给 Neo4j，并返回最新的图数据给前端。

# 实施步骤（请严格按照以下 Phase 逐一进行，每完成一个 Phase 向我确认后再进入下一个）：

## Phase 1: 基础架构搭建 (Scaffolding)
1. 初始化项目目录：创建 `frontend` (Next.js) 和 `backend` (FastAPI) 文件夹。
2. 配置后端的跨域 (CORS)、依赖文件 (`requirements.txt`)，包含 fastapi, uvicorn, openai/anthropic, pydantic, neo4j, sse-starlette。
3. 设计基础的数据库结构（SQLite建表 SQL/ORM）和 Neo4j 连接单例。

## Phase 2: Agent 逻辑与后端流式接口开发
1. 实现基础的 LLM 调用封装，支持流式输出 (Streaming)。
2. 构建 Planner Agent 逻辑：定义 Prompt 模板，使其能强制输出易于解析的章节规划结构。
3. 构建 Writer Agent 逻辑：实现按章节撰写的循环。
4. 构建 Graph Extractor Agent：编写 Prompt，使其从文本中提取 `(Entity A)-[RELATION]->(Entity B)` 格式的实体关系，并写入 Neo4j。
5. **核心接口实现:** 编写 FastAPI 路由 `/api/generate`，使用 Server-Sent Events (SSE) 技术。后端需将文本 chunk、状态信息（如“正在构思大纲”、“正在撰写第1章”）以及图谱更新数据，混合打包成统一格式推送到前端。

## Phase 3: 前端交互与可视化开发
1. 构建主界面布局：左侧为“配置与状态面板”（输入构思、显示章节目录），中间为“小说阅读/生成面板”（显示流式吐出的文字），右侧为“人物关系图谱面板”。
2. 实现对 SSE 接口的对接，解析后端传来的数据流：
   - 遇到文本 chunk：追加到当前章节视图中。
   - 遇到图谱更新数据：触发 React Flow 重新渲染节点和连线。
3. 优化前端状态管理，确保长连接中途断开时有良好的容错和重连机制。

## Phase 4: 系统整合与打磨
1. 联调测试：确保 Planner -> Writer -> Extractor 的管道顺畅，图数据库成功写入。
2. 完善 Agent 的记忆层：确保 Writer Agent 在写第 N 章时，能够获取前 N-1 章的摘要以及当前人物关系图谱的状态（将图谱作为 RAG 上下文提供给 Writer），以防人物 OOC（脱离设定）或剧情穿帮。
3. 在实际开发到 Phase 4 时，不仅要让图谱展示给用户看，更要将 Neo4j 中的人物关系反哺给大模型。当 Writer Agent 撰写新章节时，通过图谱查询当前出场人物的最新状态和相互关系，作为 Prompt 上下文（一种 GraphRAG 的应用），这能极大地提升长篇小说的连贯性。
